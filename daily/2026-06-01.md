## AI Handbook 全部 11 章总结

### 已完成清单
1. ✅ LLM — 概率模型，输出是候选结果不是事实
2. ✅ Prompt — 软约束不是安全边界，Instruction 四段式
3. ✅ Context — 上下文分五层（指令/任务/事实/知识/记忆）
4. ✅ RAG — 证据链 > 向量库，检索失败要允许拒答
5. ✅ Agent — 被约束的执行循环，工具比回答更危险
6. ✅ Frameworks — 系统边界的表达，先理解工作流再选框架
7. ✅ Vibe Coding — 人负责方向/约束/验收，Agent 负责生成/修改/执行
8. ✅ MCP — 工具接口标准，权限要在协议外也成立
9. ✅ Evaluation — 不能被重复测量的 AI 行为就不能被稳定改进
10. ✅ Fine-tuning — 改行为分布不改系统边界，先有 eval 再谈微调
11. ✅ Inference — 约束条件下交付可用答案，延迟/成本/质量/隐私的平衡

### 每章核心一句话
| 章节 | 核心观点 |
|------|----------|
| LLM | 模型输出是候选结果，不是事实本身 |
| Prompt | 软约束不是安全边界，真正边界靠代码/权限/审计 |
| Context | 模型只能基于看见的上下文行动 |
| RAG | RAG 的可靠性取决于证据链，不取决于向量库 |
| Agent | Agent 是被约束的执行循环，目标/工具/状态/权限/停止条件缺一不可 |
| Frameworks | 先理解工作流再决定用不用框架 |
| Vibe Coding | 人负责方向/约束/验收，Agent 负责生成/修改/执行 |
| MCP | 模型不应直接拥有世界，应通过明确协议访问被授权的能力 |
| Evaluation | 不能被重复测量的 AI 行为不能被稳定改进 |
| Fine-tuning | 先有 eval 再谈微调，先修数据再修模型 |
| Inference | 模型能力只有被稳定/可控/可观测地调用才算进入产品系统 |
