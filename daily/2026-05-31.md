## Handbook 学习笔记

### 1. LLM — 大语言模型

**核心观点：** 模型输出是候选结果，不是事实本身；模型能力是推理入口，不是最终验证。

**关键概念：**
- Token：模型处理的基本单位，直接影响上下文容量、成本和信息完整性
- Embedding：向量映射，用于语义搜索/RAG，但不能替代事实校验
- Transformer：擅长在上下文中找模式，但不等于拥有稳定数据库
- Hallucination：看起来合理但无法验证的内容，在带执行能力的系统里是流程风险
- Multimodal：处理更多真实工作界面，但关键判断仍要回到结构化数据

**对 ShadowAgent 的意义：**
LLM 在 ShadowAgent 中处于理解和生成层。它把用户意图转成可讨论的计划，但不能单独承担事实来源。真正的产品需要：
- 数据层：RPC、索引器、预言机、向量库
- 编排层：Prompt、Context、RAG、Agent workflow
- 执行层：工具调用、钱包、Smart Account、合约交互
- 安全层：Guard、simulation、权限策略、人工确认

### 2. Prompt — 提示词

**核心观点：** Prompt 是软约束，不是安全边界。真正的边界必须由代码、权限、校验和审计来承担。

**关键概念：**
- Instruction：任务规则，拆成四段 — 任务目标/可用输入/禁止行为/输出格式
- Few-shot：少量示例让模型模仿，但示例要跟 eval 一起维护
- Structured Output：JSON schema/函数参数，让后续代码能检查、拒绝、记录和回归测试
- Prompt Injection：攻击者通过外部内容让模型忽略规则，在 Agent 场景尤其危险

**Prompt Injection 防护核心：**
- 把外部内容标记为不可信数据
- 工具调用前做参数校验
- 敏感动作强制 allowlist + human approval
- 不把密钥、主权限和不可撤销动作交给模型

**对 ShadowAgent 的意义：**
ShadowAgent 的支付/签名流程不能只靠 prompt 拦截。需要：
- Prompt 定义任务和输出格式
- Context 提供可信数据和来源边界
- Code 校验 schema 和业务规则
- Guard/simulation 检查链上影响
- Human check 确认高风险动作

### 3. Context — 上下文

**核心观点：** 模型只能基于它看见的上下文行动；系统必须决定什么能进上下文、带着什么身份进去、过期后怎么退出。

**关键概念：**
- Context Window：一次请求能处理的最大范围，大窗口不等于完美使用
- Context Engineering：设计上下文进入模型的方式（选择/排序/裁剪/标注来源/隔离不可信内容）
- Memory：跨请求保留的信息，但不能替代实时授权
- Knowledge Base：可检索的外部知识库，需要维护来源/时间/版本/适用性

**上下文分层设计：**
1. 指令层：系统规则、工具使用规则、禁止事项
2. 任务层：用户目标、本次会话参数
3. 事实层：链上状态、工具结果、simulation
4. 知识层：文档、标准、论坛、历史案例
5. 记忆层：用户偏好和项目配置

**对 ShadowAgent 的意义：**
ShadowAgent 的 context 设计需要特别注意：
- 链上状态（余额、allowance、nonce）必须实时查询，不能缓存
- 外部 dApp 请求标记为不可信
- 隐私相关数据（Railgun 余额、Shielded TX）需要额外的权限隔离
- Memory 不能变成隐性权限假设

## 三章综合 → ShadowAgent 映射

| Handbook 概念 | ShadowAgent 对应 |
|---|---|
| LLM Hallucination | Agent 编造不存在的合约地址或错误的 gas 估算 |
| Prompt Injection | 恶意 dApp 通过交易数据注入指令 |
| Structured Output | 支付指令必须 JSON schema 校验 |
| Context 分层 | 指令层(隐私规则) / 事实层(链上状态) / 知识层(x402 spec) |
| Memory ≠ 授权 | 用户上次允许不代表本次允许，每次支付重新确认 |
| 外部内容不可信 | dApp 页面、第三方文档标记为 untrusted |
